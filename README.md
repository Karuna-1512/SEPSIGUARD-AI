# SepsiGuard AI

SepsiGuard AI is a research software workspace for inspecting longitudinal clinical measurements and connecting them to a trained GRU sequence model. It is not clinically validated and must not be used to diagnose, treat, or guide care. The included dataset and its labels are entirely synthetic; its model metrics only exercise the software pipeline.

## Clinical data contract

The model input order is fixed across the CSV importer, API, scaler, and trained GRU:

1. `heart_rate`
2. `respiratory_rate`
3. `temperature`
4. `systolic_bp`
5. `diastolic_bp`
6. `oxygen_saturation`
7. `wbc`
8. `lactate`
9. `creatinine`
10. `platelets`
11. `bilirubin`
12. `age`

`patient_id` identifies a sequence, `time_step` orders the 12 rows, and `sepsis_label` is the binary training target. The target and identifiers are never passed to the model. Training columns must be exactly `patient_id,time_step`, the 12 inputs in the order above, then `sepsis_label`. Each patient needs exactly one row for each integer time step 1–12 and one consistent label. Batch prediction accepts the same columns with or without the final label. All measurements must be finite numeric values; request validation also applies broad input bounds.

The project includes `data/sepsis_longitudinal_synthetic.csv`, generated by `backend/ml/generate_clinical_dataset.py`. To regenerate it:

```powershell
python -m backend.ml.generate_clinical_dataset --output data/sepsis_longitudinal_synthetic.csv --patients 160 --seed 17
```

The generated labels are artificial and do not represent clinical outcomes. Do not interpret performance from a model trained on this file as real-world performance.

## Train the GRU

Python 3.10–3.12 is recommended. Install the API and ML dependencies in the same environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -r requirements-ml.txt
python -m backend.ml.train --data data/sepsis_longitudinal_synthetic.csv --synthetic-data --epochs 30 --batch-size 32 --seed 42
```

The training job groups records by patient before creating train, validation, and held-out test splits. The imputer and scaler are fitted only on training-patient measurements. The GRU uses the 12 ordered inputs at each of 12 time steps. Training writes four matching artifacts into `models/`:

- `sepsis_gru.keras` — trained Keras GRU
- `scaler.pkl` — fitted imputer and standard scaler
- `feature_schema.json` — ordered input and target contract
- `metrics.json` — split information, configuration, and held-out software-evaluation metrics

Use an authorized, appropriately governed dataset for research evaluations. Metrics from synthetic inputs are only pipeline checks and do not show clinical performance. Keep the four artifacts from a single training run together. The API refuses predictions if a compatible GRU or its preprocessing artifact is unavailable or mismatched.

## Run locally

### Backend

Copy `.env.example` to `.env`. Set a unique `SECRET_KEY` and provision an initial administrator using `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` (at least 12 characters). The initial account is created once when the database is empty of that email. Then run:

```powershell
python -m pip install -r requirements.txt
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

### Frontend

```powershell
cd frontend
npm ci
npm run dev
```

Open `http://localhost:5173`. Set `VITE_API_URL` if the API is running elsewhere. FastAPI interactive documentation is available at `http://localhost:8000/docs`.

The model status endpoint reports `training_required` until the matching artifacts exist. Prediction endpoints return service unavailable in that state; no fallback scores are generated. Predictions from synthetic-trained artifacts are actual GRU outputs but remain artificial software results, not clinical risk estimates.

## API and model input

See [docs/API.md](docs/API.md) for authentication, schema, prediction, and batch upload examples. The frontend submits a patient ID, age, and ordered clinical observations. A manual request accepts between 1 and 12 consecutive time steps; CSV batch rows require a complete 12-step sequence per patient.

## Software requirements

- Python 3.10–3.12 for the API and ML pipeline
- TensorFlow/Keras 2.16–2.x, NumPy, pandas, scikit-learn, and joblib for GRU training/inference
- Node.js 20 or later and npm for the React/TypeScript frontend
- SQLite by default, or PostgreSQL using the supplied Compose configuration
- Docker Compose is optional for containerized local deployment

## Verification

```powershell
python -m pytest tests/backend
cd frontend
npm test
npm run build
```

## Deployment and limitations

For a deployment, set a strong secret, HTTPS CORS origins, secure database credentials, administrator bootstrap credentials, and paths to a reviewed model artifact set. Do not package patient data or private model weights in a public image. Add monitoring, retention controls, governance review, external validation, calibration analysis, and an approved operating protocol before considering any clinical research use. The software itself does not establish clinical validity.
